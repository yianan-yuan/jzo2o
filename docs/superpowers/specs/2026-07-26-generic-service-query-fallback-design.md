# 泛服务查询降级设计

## 目标

当用户输入“有什么服务”“有哪些服务”或“服务推荐”这类泛问时，AI 助手稳定返回当前城市真实、已上架的服务推荐，不展示模型内部错误码。

## 根因

需求理解阶段对小模型的 JSON 结果有严格字段校验。泛问没有具体服务关键词，小模型偶尔返回字段不完整或不符合语义约束的 JSON；第二次重试仍失败时，服务将 `AIGC_MODEL_OUTPUT_INVALID` 发送给小程序。

## 方案

在 `DemandUnderstandingService` 的模型调用前识别常见泛服务查询。识别到后直接构造一个无需澄清、搜索关键词为空的 `DemandDecision`。后续服务目录查询仍按用户所在城市和上架状态过滤，候选选择的既有降级逻辑会从真实候选中推荐最多三项。

保留 SSE 流式协议与明确需求的模型理解流程；只绕过不适合由小模型承担的固定泛问。

## 验收

- “有什么服务”不调用模型，也不产生 `AIGC_MODEL_OUTPUT_INVALID`。
- 该请求继续到服务目录与推荐步骤，能够返回当前城市真实服务。
- 明确需求（如“日常保洁”）保持原有行为。
