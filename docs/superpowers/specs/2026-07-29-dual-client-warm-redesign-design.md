# 云家政双端暖橙安心视觉改版设计

## 目标

为用户小程序与服务人员 App 的全部业务页面建立一致的「暖橙安心」视觉体系，在不改变接口、路由、数据字段、权限或订单流程的前提下，提升品牌温度、信息层级与移动端操作效率。

## 范围

### 用户小程序

覆盖首页、AI 助手、登录、我的、服务分类与详情、消息、城市、搜索、地址与地址编辑、优惠券、支付与成功页、评价、订单列表/详情/取消/评价，以及历史订单与详情。

### 服务人员 App

覆盖启动与登录、工作台、服务技能、接单设置、服务范围与城市、订单列表、订单详情、取消、服务记录、消息、历史订单、评价、我的、账户设置、实名认证与认证失败页。

### 不在范围内

不调整后端接口、数据模型、页面路由、登录逻辑、支付和订单状态机；不替换现有业务图片或图标资源，除非现有资源无法适配新布局。

## 视觉方向

选定方案 A「暖橙安心」。基础背景使用暖杏白，品牌主色使用珊瑚橙，深棕灰承载正文，辅以白色圆角卡片和低对比度阴影。页面保持充足留白，避免大面积饱和红色造成压迫感。

建议设计令牌：

| 用途 | 值 | 说明 |
|---|---|---|
| 页面背景 | `#FFF8F4` | 暖色、低干扰底色 |
| 卡片表面 | `#FFFFFF` | 内容与背景分层 |
| 品牌主色 | `#F06C48` | 主按钮、选中态、关键入口 |
| 品牌浅色 | `#FFF0E9` | 标签、弱提示、选中背景 |
| 主文字 | `#2C2522` | 标题与关键数据 |
| 次文字 | `#7E746F` | 说明与辅助信息 |
| 分割线 | `#F2E8E2` | 卡片与列表边界 |
| 成功状态 | `#2E9B74` | 完成、可用、在线 |
| 提醒状态 | `#E9A23B` | 待处理与时间提醒 |
| 风险状态 | `#DC5A52` | 取消、失败与高风险操作 |

圆角采用 16rpx（小控件）、24rpx（按钮/标签）、32rpx（卡片）三级；常规页面间距采用 24rpx，卡片内容采用 28rpx 内边距。

## 双端差异化原则

两端共用品牌主色、字体层级、圆角、阴影与状态色，保证用户在不同端识别为同一服务品牌。

小程序以「发现服务与安心下单」为中心：首页使用暖色服务横幅、分类入口和精选服务卡；订单和支付页强化价格、服务时间、地址与主操作；个人中心保持轻量、温和。

服务人员 App 以「快速判断与完成任务」为中心：工作台、抢单/订单、订单详情与服务记录突出订单状态、时间、距离、地址、联系电话和主操作。背景装饰减少，状态标签与行动按钮对比更强，保证户外和高频操作时可快速扫描。

## 组件与页面改造

先改造两端的共用组件，再由页面组合使用，避免同一视觉规则在多个页面复制。

| 模块 | 小程序 | 服务人员 App |
|---|---|---|
| 顶部与底部导航 | 自定义导航、底部 Tab 的暖色选中态与安全区 | 工作台导航、底部 Tab 的状态可读性与安全区 |
| 信息卡片 | 服务分类、服务详情、地址、优惠券、订单摘要 | 订单卡、服务记录、认证资料、账户信息 |
| 筛选与输入 | 搜索、城市、日期、地址和支付确认 | 订单状态 Tab、筛选、接单设置、技能与范围选择 |
| 反馈状态 | 空数据、网络失败、支付成功、评价提交 | 空订单、加载/失败、认证失败、服务完成 |
| 主操作 | 下单、支付、确认、联系客服 | 抢单、出发、开始服务、完成服务、联系用户 |

所有列表页统一使用分组卡片、清晰标题和弱分割线；详情页统一采用信息块 + 固定底部主操作区；表单页统一输入框、必填标识、说明文字和提交按钮层级。

## GitHub 管理方案

以 `D:\develop\code\jzo2o2.0\.publish-jzo2o` 的 GitHub `main` 为唯一发布仓库。服务人员 App 的现有 Gitee 仓库不修改、不重置、不移除远程；将其当前源码快照作为普通目录纳入 GitHub 仓库，不携带嵌套 `.git`。

纳管目录为 `project-xzb-app-uniapp-java`。提交时排除 `node_modules/`、`unpackage/`、`.idea/`、`.hbuilderx/`、`.vite/`、`project.private.config.json`、本地环境文件和构建缓存；保留 `package.json`、锁文件、页面/组件/样式/静态资源、配置模板和源码。

## 验收与测试

- 小程序和服务人员 App 均能通过项目现有构建命令完成编译。
- 页面路由、接口调用、登录、下单/接单及订单状态流保持原有行为。
- 核心页面在常用手机宽度下无横向溢出，固定底部操作区不遮挡内容。
- 视觉检查覆盖首页、服务/工作台、订单列表、订单详情、个人中心、表单页和空状态。
- GitHub 仓库不包含本地依赖、构建产物、IDE 文件或私有配置。

## 实施顺序

1. 将服务人员 App 的可发布源码加入 GitHub `main` 并验证忽略规则。
2. 建立两端主题令牌和页面基础背景。
3. 改造两端导航、Tab、卡片、表单、空状态和底部操作组件。
4. 依页面分组完成全部业务页面的布局与样式迁移。
5. 执行构建、路由冒烟检查和视觉检查，修复发现的问题。
