# 管理端服务记录详情修复设计

## 目标

让管理端订单详情读取到服务人员完成服务时已保存的服务前后图片、说明和服务时间。

## 根因

`OrdersServe` 以订单 ID 作为主键。服务人员端的开始和完成接口均按该主键更新服务单。管理端聚合详情却按 `orders_serve.orders_id` 查询；该字段在当前创建链路中没有赋值，查询结果为空，因而接口返回 `serveInfo = null`。

## 方案

在 `OrdersManagerServiceImpl.operationDetail(Long id)` 中按服务单主键 `id` 查询 `OrdersServe`。这是项目中服务人员详情、状态机和历史同步已采用的 ID 关联方式。

不修改数据库、不要求用户重新上传图片，也不改变服务人员端的提交接口。历史已完成订单只要 `orders_serve` 行仍存在且图片字段已写入，订单管理服务重启后即可回显。

## 验收

1. 管理端详情聚合不再按照 `OrdersServe::getOrdersId` 查询。
2. 聚合的 `ServeInfo` 继续复制开始/结束时间、前后图片和说明。
3. 静态契约测试能在旧查询写法下失败，并在新写法下通过。
