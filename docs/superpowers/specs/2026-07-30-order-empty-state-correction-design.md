# 订单空状态与状态栏修正设计

## 目标

修正服务人员端和用户小程序订单页的空状态语义、图案遮挡和状态栏横向溢出问题，使两端均保持悦家服务的暖橙视觉。

## 服务人员端

- 抢单大厅仍使用现有的服务工具箱空状态；订单页不再让空状态紧贴固定的订单状态栏，保留状态栏下方的安全间距。
- 历史订单不再复用抢单大厅的图案和“保持在线”文案，改用独立的“订单档案 + 对勾”线稿，并显示“暂无历史订单，完成服务后会显示在这里”。
- 订单页各状态没有订单时沿用服务工具箱图案，但显示“暂无{状态}订单”，不再暗示抢单机会。
- 共享标签容器采用边界盒模型，避免 H5 预览中出现横向页面溢出。

## 用户小程序

- “我的订单”空状态不再引用旧的猴子图片；订单列表显式选择“订单档案 + 对勾”代码绘制图案，保留现有“暂无订单哦～”文案。
- 五个订单状态项保持等宽；固定栏使用左右定位而非宽度与外边距叠加，左右与页面内容各保留 24rpx 间距，最后一项不得溢出屏幕。
- 顶部“历史订单”入口继续避开微信胶囊按钮，本次不改变该已修正的安全距离逻辑。

## 验收与测试

- 服务人员端订单和历史订单各自传入明确的空状态变体；历史订单不再使用抢单文案或布局覆写。
- 小程序订单列表明确选用订单空状态变体，且组件中不渲染旧猴子图片。
- 静态契约测试覆盖空状态变体、订单栏等宽规则及左右固定定位规则。
- 运行两端现有 Node 契约测试和 `git diff --check`。
