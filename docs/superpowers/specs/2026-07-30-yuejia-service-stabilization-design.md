# 悦家服务双端稳定化设计

## 目标

将用户小程序和服务人员 App 的品牌统一为“悦家服务”，修复当前已确认的交互与布局问题，并撤销服务人员 App 中破坏原有页面结构的全局样式覆盖。

## 已确认的体验问题与根因

1. 首页“日常维修”分类跳转后显示“日常保洁”。首页依赖 `activeId` 本地缓存，但服务分类接口返回后无条件选中首项，覆盖了缓存值。
2. 精选推荐图采用 `scaleToFill` 和固定高度，导致服务海报被纵向压缩。
3. 我的页面将昵称与提示语作为同一行 flex 容器的兄弟节点，并将提示语绝对定位，窄屏上发生重叠。
4. “查看全部”进入的订单列表仍是旧视觉，没有和“我的”页面的卡片层级保持一致。
5. 服务人员 App 的 `App.vue` 全局匹配 `.item` 和 `.navFrame`：前者把导航图标容器改成白色卡片，后者将首页头部撑到至少一屏高度，造成白块与大片空白。

## 设计决策

- 品牌：用户端显示“悦家服务”，服务人员端显示“悦家服务·服务端”。服务协议等法律文案仅替换其展示名称，不改变接口、包名或后端字段。
- 用户端继续使用当前暖橙色、圆角卡片与浅米色背景，不进行新的全局 CSS 覆盖。
- 首页分类通过 URL 查询参数传递目标 `serveTypeId`；分类数据加载完成后才应用该值，找不到时回退至第一个分类。缓存不再用于本次跨页选中状态。
- 推荐海报使用统一的展示框与 `aspectFill`：完整卡片尺寸稳定，图片保比例裁剪，绝不拉伸。
- 个人页头像、昵称、辅助说明改为纵向信息组；订单列表复用暖橙标题、状态筛选和卡片间距，但保持现有接口、订单状态和删除流程。
- 首页 AI 助手使用一个本地卡通人物 PNG；点击直接打开既有 `/pages/ai-chat/index`，对话接口与降级回复不变。
- 服务人员 App 的全局样式仅保留页面背景等安全基础规则。首页的导航、筛选、列表样式在各自组件中定义，禁止在 `App.vue` 对通用 `.item`、`.navFrame`、`.box` 等选择器做视觉覆盖。

## 验收条件

1. 点击首页任意服务分类后，“全部服务”高亮并加载对应分类；连续点击不同分类不受上一项影响。
2. 不同长宽比的推荐图片不会变形，卡片图片区域高度一致。
3. 我的页面昵称和“管理预约、地址与优惠”在 320px 宽度下不重叠。
4. 从“查看全部”和四个订单快捷入口进入订单页，状态筛选、返回路径与订单操作保持原逻辑。
5. AI 助手为本地卡通人物，点击进入对话页且展示欢迎语。
6. 服务人员 App 首页的顶部功能图标不再被白色卡片包裹，横幅下不出现由头部容器造成的整屏空白。
7. 两个 UniApp 项目均可被 HBuilderX 启动；不修改原始 Gitee 副本。
